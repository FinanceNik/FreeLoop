# Open questions

Decisions not yet made, each with options, a recommendation and the milestone by which it must be settled (see [ROADMAP.md](ROADMAP.md)). Closed questions move to the bottom with their outcome.

## Open

- **OQ-016 · Plugin API shape beyond hooks · needed by v1.** Options: shell hooks only (EXT-005); JSON-RPC extension processes; WebAssembly plugins. Recommendation: hooks and ACP/MCP processes through v1; decide on a richer API only when a concrete need appears that those cannot meet.
- **OQ-017 · Contribution policy · needed before accepting PRs.** Options: DCO sign-off or a CLA. Recommendation: DCO, with `CONTRIBUTING.md` and a code of conduct added at v1 scoping.
- **OQ-018 · Other vendors' subscription terms · needed by v1 (HRN-007).** Codex CLI with a ChatGPT login and Gemini CLI with a Google login are driven as unmodified binaries, the same pattern as Claude Code. Their terms need the same reading Anthropic's got before presets ship. *Checked 2026-10-25:* OpenAI's help article on using Codex with a ChatGPT plan could not be fetched (403); secondary reports say OpenAI has publicly welcomed third-party harnesses on ChatGPT subscriptions, including a sign-in for OpenClaw in May 2026, but none of that is contractual, so the Codex preset keeps the same pattern as Claude Code: unmodified binary, its own sign-in, no token handling. For Gemini CLI, Google-account sign-in for individuals (free and AI Pro) stopped working around mid-2026 with the message that the client is no longer supported for Gemini Code Assist for individuals and a pointer to the Antigravity products; the official authentication docs still describe Google sign-in and are stale. The Gemini CLI preset should therefore assume API-key authentication, with an Antigravity CLI preset as a separate later item. *Codex, checked at the source 2026-10-25:* OpenAI's Codex authentication docs and help center list Codex CLI, the IDE extension and the desktop app as clients that support ChatGPT sign-in, recommend API keys for automation, warn that `~/.codex/auth.json` holds access tokens to be treated like a password, and say nothing either way about third-party hosts launching the CLI; the ChatGPT Terms of Use apply to data shared between Codex and ChatGPT. The Codex preset therefore follows the Claude Code pattern exactly and must never read `~/.codex/auth.json` or pass credentials. *Presets built 2026-11-01 (HRN-007):* the Codex preset runs `@agentclientprotocol/codex-acp`, which hides its browser login with `NO_BROWSER=1` and selects its API-key method only when Codex is not already signed in (`DEFAULT_AUTH_REQUEST`); a `codex login` in a terminal is Codex's own and the app does not touch it, as with Claude Code. Gemini CLI still advertises Google sign-in over ACP and the app never selects it; its preset says to use an API key. Still to read: whether OpenAI's terms say anything of third-party hosts launching Codex on a ChatGPT plan.
- **OQ-024 · A Client ID Metadata Document for MCP sign-ins · needed by v1 release (MCP-006).** The MCP authorization spec prefers that a client identify itself by an HTTPS URL serving its client metadata (a Client ID Metadata Document); the app now registers itself with each authorization server through Dynamic Client Registration, or uses a client ID the user enters, because a metadata document needs a URL the project controls for as long as releases are in use. Options: host `client.json` on a project domain (stable, needs a domain and its upkeep); host it on GitHub Pages under the project's repository (free, tied to the repository's name); stay with registration only (works wherever the server allows registration, which some, such as GitHub's, do not). Recommendation: GitHub Pages now, a project domain if one comes; the document lists the loopback redirect (`http://127.0.0.1/callback`, any port) and the `authorization_code` and `refresh_token` grants, and the app passes its URL as `ClientIDMetadataDocumentConfig`.
- **OQ-030 · What a restore does with the guards its files leave out · needed by v1 release (SET-005).** A restored `rules.yaml` or profile replaces the file, so a deny rule or blocking hook the backup does not have stops applying, and a sandboxed command or a read inside the project then runs unasked. Nothing waits for approval, since nothing was added. Options: (a) tell the user: the restore's result lists them, and they can add them back; (b) keep them: a restore adds this Mac's deny rules back to the files it replaced, so only deleting one in the app ends it; (c) ask before restoring, listing what would go. Built: (a) and (c). The preview lists them before anything is written, and the result lists them after. Still the user's decision: whether to add (b). Recommendation: leave it out. A restore replacing settings is what the user asked for, the replaced files are kept in `backups/`, and the preview now says what would go. (b) is stronger, but restoring a backup to get rid of a rule would then quietly fail, and hooks have no such merge. Choose (b) if deny rules should count as this Mac's, as local-only mode now does. *Related, settled the same day and easy to reverse:* allow rules written by hand in `rules.yaml` wait for approval like hooks, rather than applying on the next tool call as SET-001 first implied; an allow rule cannot tell a hand edit from a planted one.

## Closed

- **OQ-009 · Code signing and notarization** · closed 2026-11-03 (the user chose). Not done: builds stay ad-hoc signed, with no Apple Developer account. So macOS blocks a downloaded app until the user allows it once in System Settings, under Privacy & Security, a build from source is not affected, and the Keychain may ask again after an update, because the signature changes with each build. A self-signed certificate does not stop that (tried 2026-11-03): the item's access list then trusts the app across builds, but the Keychain also keeps a partition list, and for any certificate not issued by Apple the entry there is `cdhash:<hash>`, which changes with each build, so a second build still gets the prompt. SEC-012 and NFR-SEC-004 are reworded. Checksums, the bill of materials and reproducible builds remain what a release can be checked against.
- **OQ-015 · Update mechanism** · closed 2026-11-03, following OQ-009. GitHub releases and the opt-in check that only says a newer version exists (SEC-009). A Homebrew cask and in-app updates were waiting on signed builds and are not planned.

- **OQ-023 · Default prices for cost estimates** · closed 2026-11-03 (the user asked for official API prices per model). A dated table of Anthropic's, OpenAI's and Google's list prices ships with the app and is updated with releases (`internal/config/builtinprices.go`); the user's rows in `config.yaml` come first. It is not fetched: that would be outbound traffic beyond what the user configured (SEC-009). Models served locally or through a compatible endpoint under another name have no row and show no price.
- **OQ-029 · How token optimizers apply** · closed 2026-11-02 (the user asked for a dropdown and approved the plan after a test with RTK 1.1.0). By rewriting commands after approval, through the program's `rewrite` call, for the built-in harness first. `rtk hook claude` is not used: with a repository's `.claude/settings.json` allowing `Bash(*)` it answered "allow", and a `git push` ran with no approval, proven with the real Claude Code adapter. The program is not bundled, because the `rtk` edition carries a BUSL-1.1 engine and `rtk-oss` does not; the user installs it. It is off by default, because it can cut output an agent needs (`git log` bodies, large diffs). Reopened and extended 2026-11-03, when the user asked to install and use it from a Claude Code session. Claude Code now goes through a hook of Freeloop's own in the per-session plugin that calls `rtk rewrite`; since the agent then asks about the rewritten form, read-only commands use a narrow allow list (`permission.ReadOnlyCommand`). The app also offers to download `rtk-oss` 1.1.0, Apache-2.0, pinned by checksum, on the user's click, into its own caches; it still bundles nothing. Gemini CLI, Codex and OpenCode ran their shell tools without `terminal/create`, so that route serves only custom harnesses. Two more optimizers were tested on 2026-11-03, when the user asked for others, and neither was added; RTK stays the only built-in. squeez 1.49.2 (Apache-2.0) runs commands itself with `squeez wrap`, so it would need a new optimizer type. It answered a test run with a different failure with "~90% similar, output omitted" and a changed file with "identical, output omitted"; settings turn that off. What they do not turn off: a repository's `.squeez/filters.ini` hid a `git diff` line and changed `FAIL` to `ok`, and `git show HEAD:<file>` became `201 modified`. With settings that keep everything, almost no saving was left outside those wrong answers. PTK 0.1.6 (MIT, on PyPI) has a `rewrite` command, but what it generates is `python -m ptk`, which ran a `typer.py` planted in the repository and does not start from a virtual environment. Its `git show HEAD:<file>`, `git diff --stat` and `git diff --name-only` came back empty with exit 0, `grep` kept 20 of 200 matches with no note, its repository returned 404 and it needs Python 3.11 or newer. Before adding either: squeez would need a way to turn off a repository's filters and correct `git show`; PTK, correct output and a maintained source.

- **OQ-028 · The native sandbox's defaults** · closed 2026-11-01 (the user chose the recommendations). Off by default, with a built-in "Local, sandboxed" environment offered in the new-session form; revisit once real projects have shown what breaks. Localhost reachable by default, with a per-environment switch to refuse it, because tests and dev servers need it, although it also reaches whatever else listens on the Mac. A sandboxed command runs without an approval in `ask` and `accept_edits`, and deny rules still win.
- **OQ-027 · System text size** · closed 2026-11-01 (the user chose). NFR-A11Y-002 is reworded around the app's Font size setting, which scales all text, with ⌘+ and ⌘- to change it from anywhere. The app does not follow the system's Text Size setting, since web content in a macOS app does not by itself. The View menu's page zoom is gone: it claimed those keys and ⌘0, and it scales the layout too.
- **OQ-026 · Worktree scripts in a Docker session** · closed 2026-11-01 (the user chose). In the container: setup, run and archive commands all run there, so nothing a container wrote runs on the Mac and `npm install` builds for the right system. A setup starts the container before the first message and stops it after, unless the session is using it; an archive restarts it, and is skipped when the container never started. `copy` stays on the Mac, because the main checkout is not in the container, and `$FREELOOP_ROOT_PATH` there holds at most its `.git`. The cost: `archive: docker compose down` no longer reaches the host's Docker.
- **OQ-025 · Where web search goes** · closed 2026-11-01 (the user asked for web tools and left the choice open). No default engine: the only outbound traffic the app allows itself is to endpoints the user configured, so `web_search` is offered only with `web.searchURL` set (SearXNG and Brave response shapes are read; a key, if any, stays in the Keychain). A provider's own server-side search tools were not used: they exist for some providers only, and the search would bypass the broker. Reopen if users want a one-click default.
- **OQ-006 · How skills reach external harnesses** · closed 2026-10-30 (the user left the choice to Claude). A per-session plugin folder in the app's data folder, handed to the agent at session start: the Claude Code ACP adapter passes `_meta.claudeCode.options` of `session/new` and `session/load` to the Claude Agent SDK, whose `plugins` option loads a local plugin folder with its skills, so the app writes nothing into `~/.claude` or the project's `.claude/`. The other options lose: materializing into the project's discovery folder writes into the user's repository (and for Claude Code into `.claude/`, which the app must never touch), and a per-session config directory (`CLAUDE_CONFIG_DIR`) would also move Claude Code's sign-in, which the app must stay out of (HRN-008). A preset says whether its agent takes skills this way (`skills: claude-plugin`, set on the built-in Claude Code preset); other agents get none until their configuration surface is checked (HRN-007).

- **OQ-014 · Secrets inside Docker environments** · closed 2026-10-29. As recommended: variables at exec time, for the command's process only. `docker exec -e NAME` takes the value from the docker CLI's own environment, so no secret is on a command line, in an image or in a file.

- **OQ-008 · Worktree default** · closed 2026-10-29. As recommended: worktrees stay opt-in, and the new-session form preselects one, with a line saying why, when another session already works in the project; "Remember for <project>" stores always or never on the project, which then decides without asking.

- **OQ-022 · Virtualizing the transcript** · closed 2026-10-29. (a): the conversation keeps rendering every item with `content-visibility: auto`, which measured 226 ms to open a 5,001-event transcript and at most 1.7 ms of layout per scroll step in the built-in browser. The user checks scrolling in the packaged app on an M1; a virtualized list comes only if that misses 60 fps, and GUI-003 and NFR-PERF-002 are reworded to the measured targets once it passes.

- **OQ-013 · Cross-session rate limiting** · closed 2026-10-29. A per-provider concurrency cap: at most `maxConcurrent` model calls (default 4, set per provider in `providers.yaml`) run on one provider across all sessions; a session waiting for a slot shows as queued. No token-bucket scheduler unless the cap proves too coarse.

- **OQ-005 · Claude Code adapter route** · closed 2026-10-29. (a): the ACP adapter, now published as `@agentclientprotocol/claude-agent-acp` (formerly Zed's `@zed-industries/claude-code-acp`), run with `npx` and pinned in the built-in preset; it needs Node. (b), a native driver for Claude Code's streaming JSON, stays the fallback if the adapter lags. Node is detected at onboarding and in the new-session form (2026-10-29).

- **OQ-007 · Instruction file precedence** · closed 2026-10-28. `AGENTS.md` first, `CLAUDE.md` as fallback, both read-only. Nested `AGENTS.md` files are read when the agent touches files under their directory; other vendors' files (`GEMINI.md`, `.cursorrules`) are not read.
- **OQ-010 · Permission rule syntax** · closed 2026-10-28. Freeloop's own canonical YAML syntax with explicit tool, pattern type and scope fields, plus an importer that converts Claude Code rules and reports what it could not express.
- **OQ-011 · Local model tool calling path** · closed 2026-10-28. Ollama's native API is the primary path; no prompt-based tool-call parser in M1. Models that fail the tool-calling probe are marked unsupported for the built-in harness (PRV-005).
- **OQ-019 · Shell semantics for the built-in `shell` tool** · closed 2026-10-28. `zsh -lc` by default, overridable per environment, with a timeout and output caps.
- **OQ-020 · Project identity** · closed 2026-10-28. A project is identified by its path plus a fingerprint of the first commit hash and remote URL; when a path disappears the app offers to relink.
- **OQ-012 · Event schema ownership** · closed 2026-10-28. Freeloop owns the event schema (`schemas/events.json`); it is a strict superset of ACP's `session/update` variants, so the ACP mapping is one-to-one and built-in-only events (turn boundaries, permission decisions with scope, session status, git state, errors) have a home.
- **OQ-021 · Minimum macOS version** · closed 2026-10-28. macOS 14 (Sonoma), for WKWebView features and notification APIs; set in `Info.plist` and the cgo deployment target. Revisit if a user asks for 13.
