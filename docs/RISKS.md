# Risks

Risk register for **Freeloop**. Each entry has a likelihood and impact (low, medium, high), a mitigation that is already reflected in the requirements or roadmap where possible, and the signal that says it is materializing. Review at every milestone boundary.

## Technical

- **T-01 Wails v3 is new.** Likelihood medium, impact high. v3.0.0 final shipped on 2026-10-26 and is what `go.mod` and the Makefile pin (OQ-002); the risk was written when only a beta existed. Bugs in the WebView integration on three systems, multi-window or bindings can still cost time, and the guard on engine calls depends on how Wails delivers requests (SECURITY.md, "Engine calls from a framed page"). *Mitigation:* the M0 spike passed; the exact version is pinned; keep the frontend a plain web app over a small bindings layer so a fall back to Wails v2.17, or to another shell, costs days not weeks. *Signal:* more than two days in M0 or M1 lost to shell bugs.
- **T-02 ACP evolves and the Go SDK is community-maintained.** Likelihood medium, impact medium. The official SDKs are Kotlin, Python, Rust and TypeScript; `coder/acp-go-sdk` (v0.13.x) is schema-generated by a third party and its coverage of newer methods (session list, resume, config options) is not stated. *Mitigation:* the SDK is pinned in `go.mod` (v0.13.5), not vendored; everything protocol-specific is in one adapter package (`internal/harness/acp`); its tests run against a reference agent (`acp/acptest`) on every push, and `make verify-agents` runs each preset's real agent at its pinned version, in CI weekly and on tags. *Signal:* an agent preset breaks after an agent update.
- **T-03 MCP 2026-07-28 is a breaking redesign and the server ecosystem is split.** Likelihood high, impact medium. The current revision removes the handshake and sessions, adds `server/discover`, replaces server-initiated requests with multi round-trip results, and deprecates roots, sampling, logging and dynamic client registration. Most servers in the wild still speak 2025-11-25 or 2025-06-18. *Mitigation:* use the official Go SDK, which negotiates all these revisions; implement nothing deprecated. The tests run against the SDK's own server; no test holds a server of each older revision. *Signal:* a popular server fails to list tools.
- **T-04 Local model tool calling is inconsistent.** Likelihood high, impact medium. Ollama's compatible endpoint lacks `tool_choice` and tool-call IDs, llama.cpp needs `--jinja`, LM Studio's streaming shapes deviate, small models fumble parallel calls. *Mitigation:* a per-provider and per-model capability table filled by a probe (PRV-005); correlate calls by index when IDs are missing; parallel tool calls off by default for local runtimes; clear "not supported for agent use" labelling instead of silent failure. *Signal:* bug reports that read "the agent printed the tool call instead of running it".
- **T-05 The Claude Code route breaks.** Likelihood medium, impact high for the author's own use. The ACP adapter for Claude Code (`@agentclientprotocol/claude-agent-acp`, formerly Zed's) needs Node; Claude Code releases often. *Mitigation:* the adapter version is pinned in the preset; Node is detected at onboarding; `make verify-agents` runs the real agent, in CI weekly and on tags, not nightly; a native streaming-JSON driver stays the documented fallback and is not built (OQ-005). *Signal:* adapter issues open for more than a week after a Claude Code release.
- **T-06 Concurrency bugs at ten sessions.** Likelihood medium, impact high. Leaked processes, zombie PTYs, cross-session event leaks, deadlocks in the permission queue. *Mitigation:* one context tree per session; process groups killed on cancel (job objects on Windows); the race detector in CI; tests that run three sessions in three repositories at once, crash an agent (NFR-REL-002) and race a prompt against a stop. A chaos test of ten sessions with random cancels and kills was planned and is not written. *Signal:* any transcript containing another session's events.
- **T-07 WebView performance on long transcripts.** Likelihood medium, impact medium. *Mitigation:* no virtualized list: the page lets WebKit skip layout and paint of what is off screen (`content-visibility`), events reach the window in batches, one per frame, the fold goes on from where it was, a session not on screen holds no transcript, and the store reads from where it is asked; an 80,000-event fixture with store, fold and app check timings (NFR-PERF-002). Opening a long session at its end (issue 046) is open. *Signal:* dropped frames in the fixture test.
- **T-08 Keychain friction.** Likelihood medium, impact low. macOS asks again whenever the binary's signature changes, which for an ad hoc signed app is every build (OQ-009). *Mitigation:* the Keychain is reached through the Security framework by cgo, not the `security` CLI; every secret is in one Keychain item, so a build asks for one (OQ-033); an in-memory store for tests and the app check; a stable signing identity waits for a Developer ID (OQ-057). *Signal:* Keychain prompts on every launch during development.
- **T-09 Shelling out to git and docker.** Likelihood low, impact low. Version differences in porcelain output. *Mitigation:* the diff panel and the git state parse `--porcelain=v2` only, and other status calls only ask whether git printed anything. No git version is required or detected at startup. *Signal:* diff panel errors on a specific git version.
- **T-10 Provider API drift.** Likelihood medium, impact low. *Mitigation:* thin adapters over official SDKs; each adapter's tests run against a stand-in server answering in its API's shapes, the OpenAI-compatible one in those of Ollama and LM Studio too. No test in CI runs against a real provider or runtime. *Signal:* fixture tests go red on an SDK bump.
- **T-11 Docker environment complexity (v1).** Likelihood medium, impact medium. Devcontainer CLI dependency, secrets inside containers, file permissions on bind mounts. *Mitigation:* plain `docker exec`; the app reads `devcontainer.json` itself and uses no devcontainer CLI; secrets as env vars at exec time only (OQ-014). *Signal:* v1 Docker work exceeding its three-week estimate.

## Legal

- **L-01 Anthropic's subscription terms.** Likelihood of a problem low if the boundary holds, impact high if it does not. As of 2026-10-24 Anthropic's Claude Code legal page states that OAuth sign-in is for Claude Code and other native Anthropic applications, that third-party developers may not offer Claude.ai login or route requests through Free, Pro or Max credentials for their users, and may not collect, store or intermediate Claude.ai credentials or session tokens; it explicitly allows an end user to sign in to the unmodified Claude Code binary with their own subscription, including where a platform hosts Claude Code, and says Anthropic may enforce without notice. Earlier in 2026 Anthropic blocked tools that spoofed the Claude Code harness. *Mitigation:* HRN-008 as a hard requirement; the app never passes credentials to or reads tokens from Claude Code; login copy says "sign in to Claude Code", not "sign in to Freeloop"; no modification of the binary; plain-text, factual references to Claude Code only; re-read the policy at each milestone. *Signal:* any change to Anthropic's legal page or help center on third-party use. Source: [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).
- **L-02 Other vendors' subscription terms are unverified.** Likelihood medium, impact medium. Codex CLI with a ChatGPT login would be driven the same way as Claude Code; OpenAI's Codex documentation, checked 2026-10-25, supports ChatGPT sign-in in the CLI and says nothing either way about third-party hosts launching it; the ChatGPT Terms of Use apply, so the preset keeps the Claude Code pattern and never reads `~/.codex/auth.json`. Gemini CLI no longer offers Google-account sign-in to individuals since mid-2026 (users are pointed to Antigravity), so its preset says to use an API key and a session warns when the CLI's own settings choose a Google login (`internal/engine/signincheck.go`), and the official docs are stale on this point. *Mitigation:* OQ-018, closed 2026-11-04, read each vendor's terms at the source before the presets shipped, as an engineer's reading and not advice; same pattern (unmodified binary, vendor's own sign-in, no token handling). *Signal:* a vendor announcing restrictions on third-party clients.
- **L-03 Trademarks.** Likelihood medium, impact medium. "Claude Code", "Anthropic", "Codex", "Gemini", "OpenAI" and others may be used only descriptively in plain text, never in the product name, logo or in a way that implies endorsement. The name Freeloop was confirmed on 2026-10-25 knowing that FREELOOP is registered in class 9 by third parties in the US, EU and Japan for batteries and consumer electronics, that Huawei holds FreeLoop in Korea and Japan, and that no software mark exists (OQ-001). Risk accepted; no registration is planned. *Mitigation:* descriptive use only and no claim to the mark; re-run the TMview search before the first public release and before buying domains; a `TRADEMARKS.md` note listing third-party marks, which is not written yet; no vendor logos in the UI, text labels only. *Signal:* a takedown or a naming conflict found in the search.
- **L-04 Dependency licenses.** Likelihood low, impact medium. Wails (MIT), the MCP Go SDK (MIT and Apache-2.0), `coder/acp-go-sdk` (Apache-2.0) and the official provider SDKs are compatible with Apache-2.0. Zed's Claude Code adapter is invoked as a separate process, not linked. *Mitigation:* no license scanner runs in CI; a dependency is added only after the user agrees, a test holds the shipped npm packages to five (`internal/archtest/pins_test.go`), and `make notices` writes `THIRD_PARTY_NOTICES.txt` with each release. *Signal:* a copyleft license in the notices.
- **L-05 Liability for agent actions.** Likelihood low, impact medium. An agent deletes files or runs a destructive command. *Mitigation:* Apache-2.0 warranty disclaimer; safe defaults (ask mode, protected paths, bypass gated); `docs/SECURITY.md` describing the threat model and the user's responsibilities. *Signal:* an issue reporting data loss.
- **L-06 Importing a user's Claude Code configuration.** Likelihood low, impact low. The data is the user's own and the import is one-way and local. *Mitigation:* preview before import; never write back. No action beyond that.

## Security

- **S-01 Prompt injection through repository content, tool output and MCP results.** Likelihood high, impact high. Planted instructions cause writes outside the project, exfiltration via shell or fetch tools, or permission changes. *Mitigation:* the permission broker is the only path to side effects (SEC-003); deny rules win; protected paths are absolute (SEC-005); tool output is framed as untrusted (SEC-010); bypass mode is opt-in and visibly flagged; Docker environments (ENV-005) and the native sandbox on macOS and Linux (ENV-009). *Signal:* a red-team scenario in the test suite passing when it should fail.
- **S-02 Malicious skills.** Likelihood medium, impact high. Skill scripts run with the user's privileges. *Mitigation:* preview of frontmatter and scripts on install (SKL-005); scripts run through the environment and broker like any shell call (SKL-004); no automatic updates; `allowed-tools` treated as a hint, never as a grant. *Signal:* a skill that asks to run a network command on load.
- **S-03 Malicious or compromised MCP servers.** Likelihood medium, impact high. `npx` or `uvx` commands fetch unpinned remote code; tool descriptions can carry injection; servers can exfiltrate tool arguments. *Mitigation:* trust on first start with the full command shown and a warning for unpinned remote packages (MCP-005); namespace rules so one server's tools cannot be auto-approved by accident; tool descriptions shown in the UI. No sandbox, container or host list confines a server: ENV-010's host list covers a sandboxed environment's commands, and MCP servers run outside it as the user. *Signal:* a server's tool list changing between runs without a version change.
- **S-04 Secret leakage.** Likelihood medium, impact high. Keys in transcripts, logs, child process environments, exports or screenshots. *Mitigation:* the system keyring only (the macOS Keychain, the Windows Credential Manager, the Linux Secret Service; SEC-004); env scrubbing for child processes (SEC-008); redaction by known value before persistence; exports and diagnostics exclude secrets; the UI never redisplays a saved secret. *Signal:* a grep of the config directory and transcripts finding key material (this is an acceptance test).
- **S-05 Hostile repository.** Likelihood medium, impact high. A cloned repo ships `.freeloop/` config, hooks or skills that run on open. *Mitigation:* project trust prompt before any project-level config is read (SEC-006), except its hook commands, which the trust prompt lists; hooks are inert in untrusted projects. *Signal:* any code path reading project config before the trust check.
- **S-06 Local attacker or other apps reading local state.** Likelihood low, impact medium. Transcripts contain code and possibly data. *Mitigation:* `0600` file modes and a `0700` directory on macOS and Linux, and on Windows the access rules of the user's profile folder, which the app does not change; document that transcripts are plaintext; consider at-rest encryption only if users ask. *Signal:* user requests for encryption.
- **S-07 Bypass mode misuse.** Likelihood medium, impact high. *Mitigation:* opt-in in settings, persistent banner, resets to ask on new sessions, unavailable in untrusted projects (SEC-001). *Signal:* bypass usage in bug reports about unwanted changes.
- **S-08 Supply chain of the app itself.** Likelihood low, impact high. Go modules and npm packages for the frontend. *Mitigation:* lockfiles and `go.sum` verified by `make verify-deps`, in CI when a commit runs it; minimal npm dependency count with a budget; SBOM and checksums at release (SEC-012), the checksums signed with the project's key, which an update in place checks (SEC-021); the Mac's build is signed ad hoc and not notarized until there is a Developer ID (OQ-057). The signing key is one file: lost, copies must be updated by hand once; stolen, its holder could sign a release, though only GitHub's release downloads are ever fetched. *Signal:* dependency alerts.
- **S-09 An external agent escaping the project through protocol requests.** Likelihood medium, impact high. ACP agents ask the client to read, write and run things; a careless client fulfils requests for any path. *Mitigation:* the environment's file system and exec layers enforce protected paths for every caller, protocol requests included (section 12 of ARCHITECTURE.md). *Signal:* a test agent requesting a write to the home directory succeeding.
- **S-10 Insecure local IPC after the daemon split (v1).** Likelihood low, impact medium. The split is not made; the headless API's socket exists (EXT-004). *Mitigation:* a Unix socket in the data folder, which is `0700`, or in a folder of a random name with that mode when the path is too long; no TCP listener for the API. The socket's own mode is not set and no peer credential is checked, so any process of the same user can use it (SECURITY.md, "The headless API is the user's"). *Signal:* a request to expose the API on a port. That came (GUI-052): the phone server is not this API but its own, on 127.0.0.1 only, with listed routes, paired phones and the checks in SECURITY.md row 22.

## Scope and project

- **P-01 Five pillars are too much for one person.** Likelihood high, impact high. *Mitigation:* the thin slice (M1) is one provider type each, one environment, one harness; a written cut order in the roadmap; "later" is a real list, not a euphemism. *Signal:* M1 slipping past nine focused weeks.
- **P-02 GUI polish absorbs unlimited time.** Likelihood high, impact medium. *Mitigation:* the app's own plain components and CSS, with no component library among its five npm packages; each milestone names the polish it excludes; terminal, file tree, palette and multi-window were all deferred to v1, where they were built. *Signal:* a week with no engine commits.
- **P-03 The environment matrix explodes.** Likelihood medium, impact high. Local times Docker times SSH, times built-in versus external harness, times secrets handling. *Mitigation:* the interface was in from M0 with one implementation until the MVP. Since then Docker (ENV-005), the native sandbox (ENV-009) and SSH (ENV-008) were built, and Windows and Linux added (NFR-XPLAT-003); the Windows code has not run on a Windows machine (issue 055). *Signal:* a second environment implementation before the MVP ships.
- **P-04 Every external agent has quirks.** Likelihood high, impact medium. *Mitigation:* capability negotiation drives the UI; presets ship only when their scenario passes (HRN-007); the generic ACP client is the MVP deliverable, not a list of agents. *Signal:* agent-specific branches appearing in GUI code.
- **P-05 Motivation on a personal project.** Likelihood medium, impact high. *Mitigation:* M1's definition of done is daily use of the tool itself; milestones are small and each ends with something the author uses. *Signal:* two weeks without a commit.
- **P-06 The ecosystem moves under the project.** Likelihood high, impact medium. Within the past year orchestrators have been abandoned or absorbed, protocols have had breaking revisions, and vendors have changed subscription rules twice. *Mitigation:* build on protocols, isolate adapters, keep presets as data, keep the core small. *Signal:* a dependency's repository going quiet.
- **P-07 A vendor ships the same thing.** Likelihood high, impact medium. The Claude desktop app already runs parallel sessions; editors already host ACP agents. *Mitigation:* the differentiators are the ones a vendor is unlikely to build: cross-vendor models, a cross-repo approval inbox, local-first, open source. If a vendor builds those too, the author still has the tool they wanted. *Signal:* none needed; this is accepted.
- **P-08 Contributor onboarding when the project opens up.** Likelihood medium, impact low before v1. Go plus React plus Wails plus three protocols is a lot to learn. *Mitigation:* contributor docs (NFR-REL-004, built as `docs/DEVELOPING.md`); a DCO is the recommendation and OQ-017 is still open; presets, profiles and skills as the first contribution surface since they need no Go. *Signal:* first-time contributors giving up on setup.
