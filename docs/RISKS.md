# Risks

Risk register for **freeloop**. Each entry has a likelihood and impact (low, medium, high), a mitigation that is already reflected in the requirements or roadmap where possible, and the signal that says it is materializing. Review at every milestone boundary.

## Technical

- **T-01 Wails v3 is still beta.** Likelihood medium, impact high. v3.0.0-beta.34 shipped on 2026-10-20 with no final release; APIs are declared stable but bugs in WKWebView integration, multi-window or bindings could block M1. *Mitigation:* a one-day spike in M0 that builds, signs and runs a two-window skeleton; pin the exact beta; keep the frontend a plain web app over a small bindings layer so a fall back to Wails v2.17, or to another shell, costs days not weeks. *Signal:* more than two days in M0 or M1 lost to shell bugs.
- **T-02 ACP evolves and the Go SDK is community-maintained.** Likelihood medium, impact medium. The official SDKs are Kotlin, Python, Rust and TypeScript; `coder/acp-go-sdk` (v0.13.x) is schema-generated by a third party and its coverage of newer methods (session list, resume, config options) is not stated. *Mitigation:* vendor the SDK; regenerate from the published schema when the protocol bumps; isolate everything protocol-specific in one adapter package; run the ACP compatibility kit in CI. *Signal:* an agent preset breaks after an agent update.
- **T-03 MCP 2026-07-28 is a breaking redesign and the server ecosystem is split.** Likelihood high, impact medium. The current revision removes the handshake and sessions, adds `server/discover`, replaces server-initiated requests with multi round-trip results, and deprecates roots, sampling, logging and dynamic client registration. Most servers in the wild still speak 2025-11-25 or 2025-06-18. *Mitigation:* use the official Go SDK, which negotiates all these revisions; test against one server per revision in CI; implement nothing deprecated. *Signal:* a popular server fails to list tools.
- **T-04 Local model tool calling is inconsistent.** Likelihood high, impact medium. Ollama's compatible endpoint lacks `tool_choice` and tool-call IDs, llama.cpp needs `--jinja`, LM Studio's streaming shapes deviate, small models fumble parallel calls. *Mitigation:* a per-provider and per-model capability table filled by a probe (PRV-005); correlate calls by index when IDs are missing; parallel tool calls off by default for local runtimes; clear "not supported for agent use" labelling instead of silent failure. *Signal:* bug reports that read "the agent printed the tool call instead of running it".
- **T-05 The Claude Code route breaks.** Likelihood medium, impact high for the author's own use. The ACP adapter for Claude Code is maintained by Zed and needs Node; Claude Code releases often. *Mitigation:* pin the adapter version; detect Node at onboarding; nightly integration test; keep a native streaming-JSON driver as the documented fallback (OQ-005). *Signal:* adapter issues open for more than a week after a Claude Code release.
- **T-06 Concurrency bugs at ten sessions.** Likelihood medium, impact high. Leaked processes, zombie PTYs, cross-session event leaks, deadlocks in the permission queue. *Mitigation:* one context tree per session; process groups killed on cancel; the race detector in CI; a chaos test that runs ten sessions with random cancels and kills (NFR-REL-002). *Signal:* any transcript containing another session's events.
- **T-07 WebView performance on long transcripts.** Likelihood medium, impact medium. *Mitigation:* virtualized list, delta coalescing, lazy tool output, a 5,000-event fixture in the performance test (NFR-PERF-002). *Signal:* dropped frames in the fixture test.
- **T-08 Keychain friction.** Likelihood medium, impact low. Access through the `security` CLI triggers prompts whenever the binary's signature changes, which is every dev build. *Mitigation:* a stable development signing identity; evaluate the cgo Keychain binding, since Wails needs cgo on macOS anyway; a file-backed fake for tests. *Signal:* Keychain prompts on every launch during development.
- **T-09 Shelling out to git and docker.** Likelihood low, impact low. Version differences in porcelain output. *Mitigation:* require git 2.30 or newer; parse `--porcelain=v2` formats only; detect versions at startup. *Signal:* diff panel errors on a specific git version.
- **T-10 Provider API drift.** Likelihood medium, impact low. *Mitigation:* thin adapters over official SDKs; recorded fixtures; the OpenAI-compatible adapter tested against three runtimes. *Signal:* fixture tests go red on an SDK bump.
- **T-11 Docker environment complexity (v1).** Likelihood medium, impact medium. Devcontainer CLI dependency, secrets inside containers, file permissions on bind mounts. *Mitigation:* start with plain `docker exec`; devcontainer CLI optional; secrets as env vars at exec time only (OQ-014). *Signal:* v1 Docker work exceeding its three-week estimate.

## Legal

- **L-01 Anthropic's subscription terms.** Likelihood of a problem low if the boundary holds, impact high if it does not. As of 2026-10-24 Anthropic's Claude Code legal page states that OAuth sign-in is for Claude Code and other native Anthropic applications, that third-party developers may not offer Claude.ai login or route requests through Free, Pro or Max credentials for their users, and may not collect, store or intermediate Claude.ai credentials or session tokens; it explicitly allows an end user to sign in to the unmodified Claude Code binary with their own subscription, including where a platform hosts Claude Code, and says Anthropic may enforce without notice. Earlier in 2026 Anthropic blocked tools that spoofed the Claude Code harness. *Mitigation:* HRN-008 as a hard requirement; the app never passes credentials to or reads tokens from Claude Code; login copy says "sign in to Claude Code", not "sign in to freeloop"; no modification of the binary; plain-text, factual references to Claude Code only; re-read the policy at each milestone. *Signal:* any change to Anthropic's legal page or help center on third-party use. Source: [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance).
- **L-02 Other vendors' subscription terms are unverified.** Likelihood medium, impact medium. Codex CLI with a ChatGPT login would be driven the same way as Claude Code; OpenAI's primary terms could not be fetched on 2026-10-25 and secondary reports of OpenAI welcoming third-party harnesses are not contractual. Gemini CLI no longer offers Google-account sign-in to individuals since mid-2026 (users are pointed to Antigravity), so its preset will use API keys, and the official docs are stale on this point. *Mitigation:* OQ-018 before any preset ships in v1; same pattern (unmodified binary, vendor's own sign-in, no token handling). *Signal:* a vendor announcing restrictions on third-party clients.
- **L-03 Trademarks.** Likelihood low, impact medium. "Claude Code", "Anthropic", "Codex", "Gemini", "OpenAI" and others may be used only descriptively in plain text, never in the product name, logo or in a way that implies endorsement. The name "freeloop" has not been checked. *Mitigation:* OQ-001 search before the first public release; a `TRADEMARKS.md` note listing third-party marks; no vendor logos in the UI, text labels only. *Signal:* a takedown or a naming conflict found in the search.
- **L-04 Dependency licenses.** Likelihood low, impact medium. Wails (MIT), the MCP Go SDK (MIT and Apache-2.0), `coder/acp-go-sdk` (Apache-2.0) and the official provider SDKs are compatible with Apache-2.0. Zed's Claude Code adapter is invoked as a separate process, not linked. *Mitigation:* a license scanner in CI that fails on copyleft dependencies; a `THIRD_PARTY_NOTICES` file generated at release. *Signal:* scanner failure.
- **L-05 Liability for agent actions.** Likelihood low, impact medium. An agent deletes files or runs a destructive command. *Mitigation:* Apache-2.0 warranty disclaimer; safe defaults (ask mode, protected paths, bypass gated); `docs/SECURITY.md` describing the threat model and the user's responsibilities. *Signal:* an issue reporting data loss.
- **L-06 Importing a user's Claude Code configuration.** Likelihood low, impact low. The data is the user's own and the import is one-way and local. *Mitigation:* preview before import; never write back. No action beyond that.

## Security

- **S-01 Prompt injection through repository content, tool output and MCP results.** Likelihood high, impact high. Planted instructions cause writes outside the project, exfiltration via shell or fetch tools, or permission changes. *Mitigation:* the permission broker is the only path to side effects (SEC-003); deny rules win; protected paths are absolute (SEC-005); tool output is framed as untrusted (SEC-010); bypass mode is opt-in and visibly flagged; sandboxed environments at v1 and later. *Signal:* a red-team scenario in the test suite passing when it should fail.
- **S-02 Malicious skills.** Likelihood medium, impact high. Skill scripts run with the user's privileges. *Mitigation:* preview of frontmatter and scripts on install (SKL-005); scripts run through the environment and broker like any shell call (SKL-004); no automatic updates; `allowed-tools` treated as a hint, never as a grant. *Signal:* a skill that asks to run a network command on load.
- **S-03 Malicious or compromised MCP servers.** Likelihood medium, impact high. `npx` or `uvx` commands fetch unpinned remote code; tool descriptions can carry injection; servers can exfiltrate tool arguments. *Mitigation:* trust on first start with the full command shown and a warning for unpinned remote packages (MCP-005); namespace rules so one server's tools cannot be auto-approved by accident; tool descriptions shown in the UI; network policy per environment later (ENV-010). *Signal:* a server's tool list changing between runs without a version change.
- **S-04 Secret leakage.** Likelihood medium, impact high. Keys in transcripts, logs, child process environments, exports or screenshots. *Mitigation:* Keychain only (SEC-004); env scrubbing for child processes (SEC-008); redaction by known value before persistence; exports and diagnostics exclude secrets; the UI never redisplays a saved secret. *Signal:* a grep of the config directory and transcripts finding key material (this is an acceptance test).
- **S-05 Hostile repository.** Likelihood medium, impact high. A cloned repo ships `.freeloop/` config, hooks or skills that run on open. *Mitigation:* project trust prompt before any project-level config is read (SEC-006); hooks are a v1 feature and are inert in untrusted projects. *Signal:* any code path reading project config before the trust check.
- **S-06 Local attacker or other apps reading local state.** Likelihood low, impact medium. Transcripts contain code and possibly data. *Mitigation:* `0600` file modes and a `0700` directory; document that transcripts are plaintext; consider at-rest encryption only if users ask. *Signal:* user requests for encryption.
- **S-07 Bypass mode misuse.** Likelihood medium, impact high. *Mitigation:* opt-in in settings, persistent banner, resets to ask on new sessions, unavailable in untrusted projects (SEC-001). *Signal:* bypass usage in bug reports about unwanted changes.
- **S-08 Supply chain of the app itself.** Likelihood low, impact high. Go modules and npm packages for the frontend. *Mitigation:* lockfiles and `go.sum` verified in CI; minimal npm dependency count with a budget; SBOM at release (SEC-012); signed and notarized builds. *Signal:* dependency alerts.
- **S-09 An external agent escaping the project through protocol requests.** Likelihood medium, impact high. ACP agents ask the client to read, write and run things; a careless client fulfils requests for any path. *Mitigation:* the environment's file system and exec layers enforce protected paths for every caller, protocol requests included (section 12 of ARCHITECTURE.md). *Signal:* a test agent requesting a write to the home directory succeeding.
- **S-10 Insecure local IPC after the daemon split (v1).** Likelihood low, impact medium. *Mitigation:* Unix socket with `0600` mode, peer credential check, no TCP listener by default. *Signal:* a request to expose the API on a port.

## Scope and project

- **P-01 Five pillars are too much for one person.** Likelihood high, impact high. *Mitigation:* the thin slice (M1) is one provider type each, one environment, one harness; a written cut order in the roadmap; "later" is a real list, not a euphemism. *Signal:* M1 slipping past nine focused weeks.
- **P-02 GUI polish absorbs unlimited time.** Likelihood high, impact medium. *Mitigation:* a headless component library and default styling; each milestone names the polish it excludes; terminal, file tree, palette and multi-window all deferred to v1. *Signal:* a week with no engine commits.
- **P-03 The environment matrix explodes.** Likelihood medium, impact high. Local times Docker times SSH, times built-in versus external harness, times secrets handling. *Mitigation:* the interface is in from M0 with one implementation until the MVP; Docker alone at v1; SSH unscheduled. *Signal:* a second environment implementation before the MVP ships.
- **P-04 Every external agent has quirks.** Likelihood high, impact medium. *Mitigation:* capability negotiation drives the UI; presets ship only when their scenario passes (HRN-007); the generic ACP client is the MVP deliverable, not a list of agents. *Signal:* agent-specific branches appearing in GUI code.
- **P-05 Motivation on a personal project.** Likelihood medium, impact high. *Mitigation:* M1's definition of done is daily use of the tool itself; milestones are small and each ends with something the author uses. *Signal:* two weeks without a commit.
- **P-06 The ecosystem moves under the project.** Likelihood high, impact medium. Within the past year orchestrators have been abandoned or absorbed, protocols have had breaking revisions, and vendors have changed subscription rules twice. *Mitigation:* build on protocols, isolate adapters, keep presets as data, keep the core small. *Signal:* a dependency's repository going quiet.
- **P-07 A vendor ships the same thing.** Likelihood high, impact medium. The Claude desktop app already runs parallel sessions; editors already host ACP agents. *Mitigation:* the differentiators are the ones a vendor is unlikely to build: cross-vendor models, a cross-repo approval inbox, local-first, open source. If a vendor builds those too, the author still has the tool they wanted. *Signal:* none needed; this is accepted.
- **P-08 Contributor onboarding when the project opens up.** Likelihood medium, impact low before v1. Go plus React plus Wails plus three protocols is a lot to learn. *Mitigation:* contributor docs at v1 (NFR-REL-004); DCO (OQ-017); presets, profiles and skills as the first contribution surface since they need no Go. *Signal:* first-time contributors giving up on setup.
